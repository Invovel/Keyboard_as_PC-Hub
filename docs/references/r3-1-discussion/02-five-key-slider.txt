# 五键模块与 Touch Bar 触控条的优化方案

首先明确：五键模块保持原来的布局，触控条仍然位于五键下方，不改变两者的整体关系。 五个按键可以根据实际使用价值减少到四个或三个，但不需要为了增加触控条功能而重新设计整个附件形态。

你上传的 SVG 是上一版的结构概念图，其中五键模块下方的触控条没有体现出原来的完整布局。因此，这次以你描述的 R3 方案和原有 112×76mm 五键附件、104×22×8mm 触控条为基准。

我建议把这个附件定义为一个独立的桌面快捷控制台：

- 上部是实体快捷键，用于明确、快速、可盲操作的指令。
- 下部是线性触控条，用于音量、滚动、时间轴和连续参数调节。
- 中央主体的圆屏负责显示状态、管理配置和反馈，不要求触控条自己也有显示屏。

## 一、五键模块保留几个键更合适？

推荐布局：保留五键 + 底部触控条

功能位置示意，按键图形并非现有五键的真实 19.05mm 机械坐标。实际封装继续按原五键小板和键帽尺寸布置。

我的推荐是先保留五键。因为你已经在主体上拥有圆屏、旋钮和四个软键，五键附件应该提供另一种输入体验：稳定、可盲按、可组合的实体快捷键。

| 键位 | 默认功能建议     | 可自定义功能    |
| -- | ---------- | --------- |
| K1 | 撤销 Ctrl+Z  | 任意快捷键     |
| K2 | 复制 Ctrl+C  | 剪切、截图等    |
| K3 | 粘贴 Ctrl+V  | 任意宏       |
| K4 | Profile 切换 | 应用切换、窗口管理 |
| K5 | 功能层切换（Fn）  | 长按组合、宏层   |

这里最值得保留的是 K5。

例如，按住 K5 再滑动触控条，可以把音量控制临时变成时间轴控制；松开 K5 后自动恢复音量调节。这就让五键附件与触控条真正组成一个操作系统，而不是彼此无关的六个输入设备。

如果后续确实要减少按键，我建议减为 四键而不是三键，保留三个常用操作键和一个 Fn/模式键。

## 二、类似 Mac Touch Bar，实际上有两种不同的实现目标

完整 Touch Bar

有显示画面，能动态显示图标、按钮、滑块和应用相关操作。

无屏幕线性触控条

通过手指位置、滑动和轻点控制连续参数，可配状态灯和中央圆屏反馈。

我更推荐你选择第二种。

因为完整 Touch Bar 还需要长条 OLED/LCD、显示驱动、触摸叠层、额外功耗和应用上下文管理。而你的主件已经有一块 360×360 圆屏，重复增加长条屏幕的实际收益有限。

用触控条负责输入，用中央圆屏负责显示，能让附件更薄、成本更低，也更符合模块化目标。

## 三、触控条应该多长？

对你目前的设计，104mm 外壳长度其实已经比较合适，不需要为了模仿 Mac 而强行加长。

真正决定体验的因素，是有效触摸长度、位置分辨率、响应速度和手势算法，而不是单纯的外壳总长度。

### 推荐尺寸比较

90–104 mm

这是针对桌面控制条的人体工学设计建议，不是 Apple 官方尺寸或实验测量结论。长度条按相对尺寸示意。

对于你原来的 `104×22×8 mm` 触控条，我建议这样分配尺寸：

| 参数     | 推荐初始值                     |
| ------ | ------------------------- |
| 外壳长度   | 104 mm（保留）                |
| 外壳宽度   | 22 mm（保留）                 |
| 外壳高度   | 8 mm，后续争取减薄               |
| 有效触摸长度 | 90–96 mm                  |
| 有效触摸宽度 | 12–16 mm                  |
| 两端无效边距 | 每端约 4–7 mm                |
| 触摸位置输出 | 建议至少 8-bit，优先更高分辨率        |
| 位置更新率  | 设计目标 ≥100 Hz，实际以芯片及测试结果为准 |
| 触摸响应   | 以手指输入至 HID 输出的实测延迟为准      |

如果你需要类似 Mac Touch Bar 的多点触摸或多个独立虚拟按钮，104mm 也可以研究，但需要使用支持对应多点能力的触控控制器，普通单指 Slider 芯片不能直接实现完整多点触控。

### 触控控制器的两条路线

方案 A：专用线性 Slider 控制器

例如 Microchip AT42QT2160。官方资料明确支持由连续触摸电极构成 Slider，并输出位置值。

[image](https://www.google.com/s2/favicons?domain=https://www.microchip.com\&sz=32)

microchip.com



适合单指位置检测、滑动、轻点、音量和滚动控制。电路相对简单，是最适合第一版验证的路线。

方案 B：触摸板类多点控制器

例如 Azoteq IQS572，支持 I²C、最多五指触摸和手势。

[image](https://www.google.com/s2/favicons?domain=https://www.azoteq.com\&sz=32)

Azoteq



更接近 Touch Bar 的交互潜力，但电极设计、调校、手势识别和固件工作量会明显增加。

对于目前第一版，我更推荐先采用专用 Slider 控制器。它不需要独立 MCU，直接通过磁吸 I²C 接入 ESP32。

不过，如果你决定将触控条做成可拆卸、同时支持多个安装位置，那么建议从第一版 PCB 就预留触控控制器中断、模块识别和方向检测功能。

## 五、我建议增加两项体验优化

第一项：触控反馈。 如果手指在没有任何反馈的光滑表面上滑动，用户不容易知道是否已经被系统识别。建议加入一条低亮度状态灯、在中央圆屏显示当前参数，或考虑小型触觉反馈器件。注意附件的触觉震动也需要避免干扰 eFlesh 软键和中央机构。

第二项：绝对位置与相对滑动两种模式。 这非常重要。

- 绝对位置：手指触摸最左端就表示 0%，最右端表示 100%，适合音量和参数位置设置。
- 相对滑动：无论从哪里开始触摸，都根据移动距离增加或减少数值，适合滚动、时间轴微调、窗口切换。

建议默认使用相对模式，避免手指误触到触控条末端时突然把音量跳到最大。绝对模式可以通过 Fn 组合键启用。

## 六、五键和触控条最终怎么定？

我建议目前冻结以下内容：

| 项目     | 设计结论                    |
| ------ | ----------------------- |
| 五键位置   | 保持原 R3 五键附件结构，不重新排列     |
| 按键数    | 优先保留五键，四键为后续简化候选        |
| 按键功能   | 快捷键 + Fn 功能层 + Profile  |
| 触控条位置  | 仍在五键模块前部                |
| 触控条外壳  | 104×22×8 mm 暂时保留        |
| 有效触摸长度 | 目标 90–96 mm             |
| 触控方式   | 电容式连续位置 Slider          |
| 控制器    | 先验证 AT42QT2160 类专用控制器   |
| 通信     | I²C + INT，连接 ESP32-S3   |
| 交互反馈   | 主体圆屏，状态灯可选              |
| 可拆卸设计  | 预留，但不为了换位缩短当前 104mm 触控条 |

我的最终建议：保留五键，把 104mm 触控条作为一个真正的高精度、连续位置输入设备，而不是把它做成几个电容按钮。

如果你的目标是类似 Mac Touch Bar 的操作体验，而不是必须有同样的长条显示屏，104mm 已经是一个合理的设计起点。接下来最关键的工作不是继续增加长度，而是选定触控 IC、电极形状、有效触摸区域和手势交互方式，再与原五键小板的机械尺寸一起定型。
