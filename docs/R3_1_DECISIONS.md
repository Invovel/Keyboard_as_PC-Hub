## 冻结、候选与阻塞

| 等级 | 决策 |
| --- | --- |
| 冻结的架构要求 | 唯一电脑上行在Core PC-C；Dock仅经P4下游连接，单向向Core供电；MAG不承载高速USB或全机电流 |
| 冻结的保留项 | 原固件/GPIO、短四键、两端留白、五键+横条、中心环屏、Touchpad延迟本轮不优化 |
| 候选 | Core 228×76、PCB216×64、USB7206C、底部48×18功能预留区、8mm板间距研究、Dock20mm高度示意 |
| 尚未冻结 | Hub最终型号/供电配置、Core自身功耗、每口允许电流、CC/Mux/保护料号、Dock连接器、实际孔位/贴装面/屏幕FPC/传动结构 |
| 必须阻塞布局放行 | 上游电力不足时的可用功能边界未实测；Dock完整配对连接器/高度未冻结；高速与中央机构未完成真实封装干涉核对 |

WP0文档及展示迁移完成不等于Rev A单线工作通过。WP1/WP2本轮交付为资料审查和有尺寸的空间研究；实际原理图、封装、布线、ERC/DRC、叠装和USB实测尚未执行。

## 下一步最小工作包

先测现有主体在低背光、正常UI、音频峰值和Wi-Fi关闭/开启时的5V电流；再核对候选Hub的配置与功耗，建立至少“Core+键盘”和“Core+键盘+接收器”两种单线负载表。之后冻结一套Dock DATA/PWR/CTRL配对连接器及堆叠高度，才进入Rev A电气原理图和真实PCB布局。若默认USB供电不足，降低可用外设/背光/声音等功能预算并明确主机兼容条件，不能把可选Dock偷偷变成启动必需品。
